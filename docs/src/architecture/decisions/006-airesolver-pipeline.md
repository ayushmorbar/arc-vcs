# ADR 006 - The AiResolver Static Analysis Sandwich

| Field      | Value                                                                      |
| ---------- | -------------------------------------------------------------------------- |
| Status     | Accepted                                               |
| Date       | 2026-04-07                                                                 |
| Deciders   | arc core architecture, AI integration, and security governance maintainers |
| Applies To | AI-assisted semantic merge resolution pipeline                             |

## Context

Legacy line-based merge systems fail at semantic intent.

1. Traditional `diff3`-style conflict handling reasons over lines instead of AST and dependence structure.
2. This produces false conflicts, hidden semantic breaks, and brittle manual repairs in complex refactors.

Naive AI conflict tooling fails at reliability and safety.

1. Feeding raw `<<<<<<< HEAD` conflict text to an LLM invites hallucinated syntax and non-compiling output.
2. Unconstrained token generation cannot guarantee behavioral preservation, type safety, or security constraints.

arc requires a deterministic envelope around stochastic generation.

## Decision

arc mandates a four-phase AiResolver pipeline, the "Static Analysis Sandwich":

1. Inbound static analysis constrains what the model sees.
2. Constrained generation constrains what the model may emit.
3. Outbound formal verification constrains what can pass.
4. Cryptographic human sponsorship constrains what can become stable history.

AI output is advisory and provisional until all post-conditions pass and a human signature is attached.

## Phase 1 - Inbound Static Analysis (Context Extraction)

AiResolver must never receive flat unresolved merge text as its primary representation.

Mandates:

1. AST Atomization: all candidate merge deltas are represented as typed AST atoms, not line hunks.
2. Interprocedural PDG slicing: build semantic dependency slices around conflicting atoms to isolate impact cone.
3. Edit-aware embeddings: embed structural neighborhood and dependency context for retrieval/ranking.

Boundary:

1. The model input contract is a typed, bounded context packet generated by static analysis layers.

## Phase 2 - Constrained Sequence Generation (AI Core)

AiResolver generation is constrained to structural operations rather than unconstrained token streams.

Mandates:

1. Pointer-network-style synthesis over existing AST nodes and typed insertion slots.
2. Explicit operation vocabulary (move, replace, insert, preserve) over free-form text rewrites.
3. Optional natural-language "vibe" descriptors are allowed only as ranking/selection hints, never as a bypass of structural constraints.

Boundary:

1. Model output must map to valid AST edit candidates and cannot directly mutate DAG state.

## Phase 3 - Formal Verification (Outbound Static Analysis)

Every AI candidate must be mechanically validated before it is eligible for sponsorship.

Mandates:

1. Zero-delta verification: recompute conflict/interference analysis and require neutralized behavioral interference for accepted candidate.
2. Formal vulnerability checks: encode critical safety predicates and run SMT-backed checks (for example Z3 bounds/path constraints).
3. Type-safe slicing: guarantee resulting edits are well-formed and type-compatible in affected slices.

Boundary:

1. Any failed verification immediately rejects the candidate and preserves deterministic fallback behavior.

## Phase 4 - Cryptographic Human Sponsorship

AI cannot autonomously finalize history.

Mandates:

1. Introduce a Ghost Node state for AI proposals: unsigned, provisional CRDT state not yet eligible for stable history.
2. Promotion to stable state requires explicit human sponsorship via `Ed25519` signature.
3. Unsponsored AI output remains non-authoritative and cannot be broadcast as stable DAG history.

Boundary:

1. Cryptographic authorship is the final gate from stochastic proposal to immutable operational history.

## Consequences

Positive:

1. Strong semantic and cryptographic guardrails around AI-assisted merges.
2. Substantial reduction of syntactically broken and semantically unsound auto-merges.
3. Explicit accountability chain from proposal to sponsored state transition.

Trade-offs:

1. Heavy prerequisite computation (PDG construction, slicing, SMT checks) before model invocation.
2. Increased local or daemon-assisted analysis workload and latency.
3. More complex implementation and observability requirements across analysis and verification layers.

## Enforcement Notes

1. Math crates remain pure and deterministic; no direct model I/O or filesystem/network side effects.
2. AI invocation and sponsorship UX live in boundary crates and daemon/CLI surfaces.
3. Verification artifacts and sponsorship metadata must be logged for auditability.
